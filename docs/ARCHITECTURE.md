# AI orchestration architecture

Hive has an authenticated, owner-scoped workflow API, a PostgreSQL durable run queue, a separate worker, and a private local model runner protected by a shared bearer token. The browser manages model downloads, typed workflow graphs, and run progress/output previews. The runner stores recoverable download state in its persistent model-cache volume; the API adds owner-scoped direct workflow and Custom Node reference counts to model status. Google sign-in and existing session controls protect private workflows and artifacts.

A workflow node is an input, a model, a built-in processing operation, an Instagram publishing operation, or a reusable Custom Node. Text inputs hold text; Image/Audio inputs reference immutable uploaded artifacts. Model nodes reference the seeded model catalog and contain bounded inference parameters. Processing and publishing nodes use static typed ports and validated settings without a downloaded model. Text Overlay can optionally add a full-width background strip behind its connected text, with color, opacity, and vertical padding settings. Custom Nodes are workflow definitions with a saved selection of internal input/output ports and caller-facing labels; a selected port may also have internal connections. All node data inputs, including prompts and captions, arrive through edges using canonical datatypes and explicit source/target port keys. Required counts, repeated inputs, and cross-port groups are validated against the node I/O contract.

The worker executes nodes in dependency order. Input nodes publish typed data without inference. Processing nodes run deterministic local transformations (currently Text Overlay, which composites connected text onto an image as PNG). Model nodes resolve connected text/files, persist settings for retries, and send requests to allow-listed text, image, video, or audio runner adapters. Qwen3-0.6B and Qwen3-1.7B generate text from connected text and node instructions; the generated Text output can feed later model or publishing nodes. Workflow publishing nodes stage generated images or videos and captions for Instagram Post/Reel publication. The separate Publish page reviews owner-scoped workflow publications awaiting review one at a time: approval records `reviewed_at` while keeping the publication and run publishable; skips are session-only; discard marks the publication reviewed and discarded and changes an awaiting-publish run to succeeded. Reviewed publications stay available in the composer until selected or reserved. Saved Media Library copies remain independently publishable. The page also composes standalone posts and image carousels from owner-scoped Media Library images and workflow publications awaiting review. Ordered carousel items carry their own alt text. Selecting a workflow image reserves its source publication until the draft is deleted or published; confirmed Instagram publication marks the source publication and its run successful. Instagram OAuth tokens are encrypted in PostgreSQL; media is served to Meta through short-lived signed HTTPS URLs. Manual workflow publication pauses its run in `awaiting_publish` until review; standalone drafts have no run lifecycle. Automatic workflow publishing and standalone publish-now actions use the publication worker. Workflow publication failures return to review without finishing the run; standalone failures return to the Publish page's review/history state. Publishing or discarding a workflow publication makes its run terminal. Kokoro text-to-speech produces WAV output; its voice and speed are stored in node settings. For image generation, the API checks queued and remaining run steps before each request; the dedicated spawned process retains its pipeline when another queued step uses the same model and releases it when no matching work remains. Worker requests carry unique IDs and send an explicit runner cancellation when the run is cancelled or its lease is lost; the runner cancels and reaps only the matching child, including requests waiting for the shared inference lock. Cancellation arriving before inference registration is retained briefly so multipart parsing cannot lose it. Cancellation, timeout, failure, non-image generation, and runner shutdown terminate that process; video, audio, and text generation use temporary processes. See [decision 0040](decisions/0040-explicit-runner-generation-cancellation.md). Artifact files use opaque keys outside PostgreSQL; their metadata and reads are owner-scoped. The independent cleanup worker also processes durable media-only cleanup jobs, rechecking each artifact's age, ownership, run state, and references before deleting file metadata and bytes. It retains run records and records per-item cleanup outcomes for retry and review.

Before a run is queued, nested Custom Nodes are recursively expanded into a single ordinary workflow graph with isolated node/edge IDs. The expanded definition is validated and stored in the immutable run snapshot, so workers do not need custom-node lookups and already queued runs are unaffected by later edits. Interface signature changes mark dependent workflows and Custom Nodes **Needs attention**; that state is recomputed through the dependency chain when definitions are repaired. Deletion confirms direct and transitive usage counts, removes the definition, and leaves missing-node placeholders in dependent graphs. Updating a stale reference reconnects ports only when their case-sensitive names and datatypes match.

Users can delete queued or terminal runs. Deleting a queued run atomically cancels it before adding its generated artifact keys and candidate input-upload IDs to the PostgreSQL cleanup outbox. The worker removes files idempotently, then deletes the run and cascaded node/artifact metadata. Uploaded inputs are removed only when no saved workflow or other run still references them. Failed cleanup retries with backoff and can be retried from Runs; model caches remain untouched. A running run must first be stopped and reach a deletable state.

The Run comparison workspace uses two owner-scoped run-detail responses to show differences between stored snapshots, node states, inputs, outputs, and artifact metadata. Its run picker adds owner-scoped pagination, search, and workflow filtering. Comparisons are read-only and diagnostic; active runs can be refreshed, and artifact bytes are loaded only for the selected node's previews. See [decision 0039](decisions/0039-run-comparison-workspace.md).

Workflow jobs are durable PostgreSQL records polled by the worker. A job queues one run at a time; after the run finishes, an interval is measured from that finish before the next occurrence is eligible. The run queue contains only actual runs, never future occurrences. Pausing prevents future queueing, and removing a job prevents future runs while preserving its existing run history.

Instagram account connections, one-use OAuth states, and publication records are owner-scoped PostgreSQL entities. Deleting a run explicitly removes its publication rows in the cleanup worker after the run is eligible for deletion. Runs with unresolved publications cannot be removed, and connected accounts with publication history cannot be disconnected until that history is deleted. Hive can prepare and download a centered square crop of a selected profile image for the user to upload manually; it does not update Instagram profile details through the API.

Workflow and Custom Node saves replace the current graph transactionally. Runs retain immutable graph/model-contract/input snapshots, with no separate workflow history. Upload references in workflows and run nodes prevent deletion of files still in use. See [decision 0019](decisions/0019-direct-model-and-input-workflows.md) for the authorized clean cutover, [decision 0028](decisions/0028-reusable-custom-nodes.md) for Custom Nodes, and [DATA_MODEL.md](DATA_MODEL.md) for current tables.

Workflow queue pausing is per user, stored in `users.runner_status`, and enforced when workers claim runs. A pause waits for that user's currently leased workflow runs to finish, then leaves their queued runs waiting; it does not pause other users, the separate Instagram publisher, or cleanup work. Active pages poll their own state while visible. Navigation run counts refresh on relevant client actions and poll while that user's queue has active work and is not paused.
