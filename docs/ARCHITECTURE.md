# AI orchestration architecture

Hive has an authenticated, owner-scoped workflow API, a PostgreSQL durable run queue, a separate worker, and a private local model runner. The browser manages model downloads, typed workflow graphs, and run progress/output previews. Google sign-in and existing session controls protect private workflows and artifacts.

A workflow node is an input, a model, or a built-in processing operation. Text inputs hold text; Image/Audio inputs reference immutable uploaded artifacts. Model nodes reference the seeded model catalog and contain bounded inference parameters. Processing nodes use static typed ports and validated operation settings without a downloaded model. All node data inputs, including prompts, arrive through edges using canonical datatypes and explicit source/target port keys. Required counts, repeated inputs, and cross-port groups are validated against the node I/O contract.

The worker executes nodes in dependency order. Input nodes publish typed data without inference. Processing nodes run deterministic local transformations (currently Text Overlay, which composites connected text onto an image as PNG). Model nodes resolve connected text/files, persist seed/settings for retries, and send requests to allow-listed image, video, or audio runner adapters. Kokoro text-to-speech produces WAV output; its voice and speed are stored in node settings. The runner executes each generation in a temporary process and reaps it on success, failure, cancellation, disconnect, or timeout. Artifact files use opaque keys outside PostgreSQL; their metadata and reads are owner-scoped.

Users can delete queued or terminal runs. Deleting a queued run atomically cancels it before adding its generated artifact keys and candidate input-upload IDs to the PostgreSQL cleanup outbox. The worker removes files idempotently, then deletes the run and cascaded node/artifact metadata. Uploaded inputs are removed only when no saved workflow or other run still references them. Failed cleanup retries with backoff and can be retried from Runs; model caches remain untouched. A running run must first be stopped and reach a deletable state.

Workflow jobs are durable PostgreSQL records polled by the worker. A job queues one run at a time; after the run finishes, an interval is measured from that finish before the next occurrence is eligible. The run queue contains only actual runs, never future occurrences. Pausing prevents future queueing, and removing a job prevents future runs while preserving its existing run history.

Workflow saves replace the current graph transactionally. Runs retain immutable graph/model-contract/input snapshots, with no separate workflow history. Upload references in workflows and run nodes prevent deletion of files still in use.
