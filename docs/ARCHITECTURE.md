# AI orchestration architecture

Hive has an authenticated, owner-scoped workflow API, a PostgreSQL durable run queue, a separate worker, and a private local model runner. The browser manages model downloads, typed workflow graphs, and run progress/output previews. Google sign-in and existing session controls protect private workflows and artifacts.

A workflow node is an input, a model, a built-in processing operation, an Instagram publishing operation, or a reusable Custom Node. Text inputs hold text; Image/Audio inputs reference immutable uploaded artifacts. Model nodes reference the seeded model catalog and contain bounded inference parameters. Processing and publishing nodes use static typed ports and validated settings without a downloaded model. Custom Nodes are workflow definitions with a saved selection of internal input/output ports and caller-facing labels; a selected port may also have internal connections. All node data inputs, including prompts and captions, arrive through edges using canonical datatypes and explicit source/target port keys. Required counts, repeated inputs, and cross-port groups are validated against the node I/O contract.

The worker executes nodes in dependency order. Input nodes publish typed data without inference. Processing nodes run deterministic local transformations (currently Text Overlay, which composites connected text onto an image as PNG). Model nodes resolve connected text/files, persist settings for retries, and send requests to allow-listed text, image, video, or audio runner adapters. Qwen3-0.6B and Qwen3-1.7B generate text from connected text and node instructions; the generated Text output can feed later model or publishing nodes. Publishing nodes stage generated images or videos and captions for Instagram Post/Reel publication. Instagram OAuth tokens are encrypted in PostgreSQL; media is served to Meta through short-lived signed HTTPS URLs. Manual publication pauses a run for caption review. Automatic publishing runs through the worker. Publication failures return to review without finishing the run. Runs in this state do not release their repeating Job; publishing or discarding the publication makes the run terminal and allows the Job interval to advance. Kokoro text-to-speech produces WAV output; its voice and speed are stored in node settings. The runner executes each generation in a temporary process and reaps it on success, failure, cancellation, disconnect, or timeout. Artifact files use opaque keys outside PostgreSQL; their metadata and reads are owner-scoped. The independent cleanup worker also processes durable media-only cleanup jobs, rechecking each artifact's age, ownership, run state, and references before deleting file metadata and bytes. It retains run records and records per-item cleanup outcomes for retry and review.

Before a run is queued, nested Custom Nodes are recursively expanded into a single ordinary workflow graph with isolated node/edge IDs. The expanded definition is validated and stored in the immutable run snapshot, so workers do not need custom-node lookups and already queued runs are unaffected by later edits. Interface signature changes mark dependent workflows and Custom Nodes **Needs attention**; that state is recomputed through the dependency chain when definitions are repaired. Deletion confirms direct and transitive usage counts, removes the definition, and leaves missing-node placeholders in dependent graphs. Updating a stale reference reconnects ports only when their case-sensitive names and datatypes match.

Users can delete queued or terminal runs. Deleting a queued run atomically cancels it before adding its generated artifact keys and candidate input-upload IDs to the PostgreSQL cleanup outbox. The worker removes files idempotently, then deletes the run and cascaded node/artifact metadata. Uploaded inputs are removed only when no saved workflow or other run still references them. Failed cleanup retries with backoff and can be retried from Runs; model caches remain untouched. A running run must first be stopped and reach a deletable state.

Workflow jobs are durable PostgreSQL records polled by the worker. A job queues one run at a time; after the run finishes, an interval is measured from that finish before the next occurrence is eligible. The run queue contains only actual runs, never future occurrences. Pausing prevents future queueing, and removing a job prevents future runs while preserving its existing run history.

Instagram account connections, one-use OAuth states, and publication records are owner-scoped PostgreSQL entities. Deleting a run explicitly removes its publication rows in the cleanup worker after the run is eligible for deletion. Runs with unresolved publications cannot be removed, and connected accounts with publication history cannot be disconnected until that history is deleted. Hive can prepare and download a centered square crop of a selected profile image for the user to upload manually; it does not update Instagram profile details through the API.
