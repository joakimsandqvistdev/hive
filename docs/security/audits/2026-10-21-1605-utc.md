## Findings

### HIVE-SEC-2026-002 — Upload admission remains process-local; deployment-wide resource bound is unknown

- Severity and rationale: Medium. The earlier confirmed issue was that concurrent authenticated uploads could buffer large request bodies before quota enforcement. The code now admits at most one upload per user and two uploads per API process before the raw parser. The cap is process-local; a multi-process deployment can multiply buffered-body memory, while deployed proxy buffering, replica count, and API memory limits are unknown. This is a residual availability concern, not a claim that local admission control is absent.
- CVSS: Not scored; deployment exposure and process count are unknown, and no supported vector was assessed.
- Confidence: High that the cap is per-process; medium for exploitability/impact in deployment because runtime topology is unknown.
- Status: Change made, verification pending.
- Location: [`apps/api/src/artifactUploadAdmission.ts`](../../apps/api/src/artifactUploadAdmission.ts); upload route in [`apps/api/src/artifacts.ts`](../../apps/api/src/artifacts.ts).
- Evidence: Admission middleware runs before Express `raw({ limit: "50mb" })`, permits at most two active uploads per process and one per user, rejects excess requests with 429, and releases capacity on finish/abort/close. The focused local HTTP check in the verification report exercised same-user and process-wide rejection successfully. The control does not cap aggregate requests across multiple API processes or proxies that buffer request bodies before forwarding.
- Impact and preconditions: An authenticated client must reach the API, and the deployment must permit enough concurrent buffered bodies without a trusted edge or memory bound to impair API availability. Actual reachability and impact depend on deployment configuration.
- Remediation: Confirm and document API replica count and memory limits; enforce a trusted-edge concurrent request/body-size bound across replicas, or use shared admission/streaming with bounded buffers. Re-run a deployment-representative concurrency test.
- Resolution target: Medium — 30 calendar days from confirmation, per Hive's target. First confirmed 2026-10-21; target 2026-11-20. This is a Hive target, not an OWASP SLA.
- ASVS: [`v5.0.0-V2.4.1`](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x11-V2-Validation-and-Business-Logic.md) — excessive calls that can exhaust resources; [`v5.0.0-V15.2.2`](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x24-V15-Secure-Coding-and-Architecture.md) — availability loss from resource-demanding functionality.
- Related evidence: [prior audit](2026-10-21-1457-utc.md), [fix record](../fixes/2026-10-21-1501-utc.md), [verification report](../verifications/2026-10-21-1504-utc.md).
