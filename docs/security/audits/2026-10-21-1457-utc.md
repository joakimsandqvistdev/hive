## Findings

### HIVE-SEC-2026-002 — Concurrent uploads can exhaust API memory before quotas run

- Severity and rationale: Medium. An authenticated client can issue multiple requests, each with a body up to 50 MB. The API buffers each body before checking artifact quotas, so concurrent requests can consume substantial process memory and impair API availability. The impact depends on deployment memory and upstream request controls.
- Confidence: High for the code path; deployment exposure and practical impact depend on unavailable runtime configuration.
- Status: Open
- Location: `apps/api/src/index.ts:33`; `apps/api/src/artifacts.ts:202-220`
- Evidence: The authenticated artifact router runs before the upload route. The route's raw body parser allows up to 50 MB and completes before the handler validates the bytes or calls `withArtifactQuota`. The code checks quota only after `req.body` is available. No per-user or global request concurrency limit is applied before body parsing. Local Compose publishes the API on loopback; production exposure and any upstream request limits were unavailable for review.
- Impact and preconditions: A valid Hive account and an API deployment reachable by the client are required. The client must send concurrent requests; it can set the accepted Origin header when using a direct HTTP client. If no upstream concurrency or body-buffering limits exist, buffered bodies can consume enough memory to slow or terminate the API process.
- Remediation: Bound concurrent upload requests per user and globally before body parsing, and apply request-rate limits at the API or trusted edge. Prefer streaming uploads to temporary storage with bounded concurrent streams and incremental size validation, then perform quota admission before final persistence.
- ASVS: [`v5.0.0-V2.4.1`](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x11-V2-Validation-and-Business-Logic.md) — anti-automation controls for excessive calls that can cause denial of service; [`v5.0.0-V15.2.2`](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x24-V15-Secure-Coding-and-Architecture.md) — defenses against availability loss from resource-demanding functionality.
