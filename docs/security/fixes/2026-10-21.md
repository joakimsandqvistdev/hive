## HIVE-SEC-2026-001 — Authenticated users can exhaust shared artifact storage

- Status: **Change made, verification pending**
- Change: Added database-serialized quota admission for every artifact creation path: direct upload, URL import, image conversion for publishing, video processing, text overlay, and model output. A PostgreSQL transaction advisory lock protects the usage check, file write, and metadata insert so concurrent API or worker writes cannot race past the limit. Local Compose passes the quota settings to both the API and workflow worker.
- Defaults: 1 GiB and 1,000 artifacts per user; 10 GiB and 100,000 artifacts for the instance. Operators can set `ARTIFACT_USER_QUOTA_BYTES`, `ARTIFACT_USER_QUOTA_FILES`, `ARTIFACT_TOTAL_QUOTA_BYTES`, and `ARTIFACT_TOTAL_QUOTA_FILES`. The instance byte limit should be set below the available artifact volume capacity.
- User-facing behavior: New artifact creation returns `429 storage_quota_exceeded` with scope `user` or `instance` when a quota is reached. Existing storage cleanup can free capacity.
- Verification still needed: Exercise quota rejection, deletion/retry, and concurrent admissions against a running PostgreSQL-backed API and worker. Type checking does not prove the database lock and quota behavior at runtime.
- ASVS mapping: [`v5.0.0-V2.4.1`](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x11-V2-Validation-and-Business-Logic.md), [`v5.0.0-V5.2.4`](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x14-V5-File-Handling.md), [`v5.0.0-V15.2.2`](https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x24-V15-Secure-Coding-and-Architecture.md)
