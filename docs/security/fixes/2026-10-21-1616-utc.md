### HIVE-SEC-2026-002 — Shared upload admission added; integrated verification pending

- Status: **Change made, verification pending**.
- Change: Replaced the process-only global upload counter with two PostgreSQL session-level advisory-lock slots. Every API process using the shared database must acquire a slot before Express's 50 MB raw body parser can buffer the upload. The existing one-upload-per-user and two-upload-per-process checks remain as local fast limits. Capacity is released on response completion or request abort/close; if the shared database is unavailable, the request fails closed through the API error handler.
- Files: `apps/api/src/artifactUploadAdmission.ts`; `apps/api/tests/artifactUploadAdmission.test.ts`; `apps/api/package.json`; `.github/workflows/ci.yml`.
- Checks: `npm run test:runner -w @hive/api` passed (31 tests, including cross-process admission simulation, release on abort, and fail-closed behavior). `npm run typecheck -w @hive/api` passed. A local PostgreSQL smoke check with three independent connections confirmed that two clients acquire the two shared slots, a third cannot acquire either, and a slot becomes available after unlock. It used only session advisory locks and did not read or modify application records.
- Verification needed: Exercise the actual admission middleware across separate API processes with overlapping HTTP uploads, including abort/disconnect handling. Review production reverse-proxy buffering, API/database topology, and resource limits. The unit test uses a shared in-memory lock fake, and the PostgreSQL smoke check validated the database primitive only; neither proves the integrated HTTP path or deployed edge behavior.
- Reason verification is pending: No local PostgreSQL-backed multi-process HTTP check or production deployment evidence was used in this fix workflow.
- Resolution target: Medium — 30 calendar days from confirmation. First confirmed 2026-10-21; target 2026-11-20 (Hive target).
