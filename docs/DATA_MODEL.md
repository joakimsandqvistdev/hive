## Database entities and relationships

- Use `/apps/api/src/schema.ts` as reference to the current database entities and relationships.

The shared model catalog uses `models` for stable model IDs and modality, `data_types` for the currently supported media types (`text`, `image`, `video`), and `model_data_types` for each model's input and output ports. A port records its key, data type, UI label, input delivery (`prompt` or workflow connection), and minimum/maximum count. A positive minimum makes the input required. Image masks use the `image` data type and the semantic `mask` port key.

`model_input_groups` and `model_input_group_ports` express constraints across ports, such as requiring one input from a choice of text or image. Port-level counts still apply within a group. Current models do not need an alternative-input group, but the schema and validator support it. Prompts remain node configuration values rather than graph edges. The `GET /api/models/contracts` endpoint returns the registry contracts to the workflow editor.

Implemented agent records use the `agents` table in `/apps/api/src/schema.ts`. Each agent belongs to one user and has either the `image` or `video` modality, with a name, prompt, and model parameters stored as JSONB. Agents can use only a model that has been downloaded to the local runner. A case-insensitive unique index prevents duplicate names within one user's library; a user/creation-time index supports paginated listing. Migration `0014_black_tempest` adds the video modality without changing existing agents. The unused legacy `tasks` table is removed by migration `0013_free_charles_xavier`.

Workflows store one current definition. `workflow_nodes` contains the current node and agent configuration rows, and `workflow_edges` contains their directed connections plus source/output and target/input port keys. Saving replaces these rows transactionally; there is no workflow version history. The API validates edge data types and port cardinalities against the model registry. Owner-scoped foreign keys ensure workflow nodes and edges belong to the workflow owner, connections stay within one workflow, and restrictive agent references prevent deleting agents used by a current workflow. A run snapshot copies the selected model I/O contract so later registry edits cannot reinterpret a queued run.

Run outputs are PNG or MP4 files in the local artifact directory. The `artifacts` table stores owner/run/node metadata, media type, byte size, checksum, display name, and opaque storage key; binary data stays outside PostgreSQL. The larger-scale storage proposal is described in [ORCHESTRATION_MVP_DESIGN.md](ORCHESTRATION_MVP_DESIGN.md#storage-choice).
